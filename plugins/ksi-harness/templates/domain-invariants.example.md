# `## 도메인 불변식` 스캐폴딩 (프로젝트 CLAUDE.md용)

> 멀티액터·금전·평판·권한 surface를 가진 프로젝트는 이 섹션을 **프로젝트 CLAUDE.md에 SSOT로** 둔다.
> 2층 구조: 전역 CLAUDE.md = 4 어뷰징**클래스**, 프로젝트 = **구체값**.
> `/codebase-audit`의 '어뷰징·무결성' 렌즈가 이 섹션을 조준점으로 측정한다 — 섹션이 없으면(코드/테스트에만 흩어지면) 렌즈가 겨눌 과녁이 사라진다.
> canonical 헤더(`## 도메인 불변식`)를 그대로 쓴다 — "Key Principles"/"Product rules" 등 이질 헤더는 렌즈가 못 앵커한다.

아래를 프로젝트 CLAUDE.md에 복사해 구체값으로 채운다(해당 클래스만 — 단일 actor·단일 CRUD면 이 섹션 자체가 불필요):

```md
## 도메인 불변식 (위반 절대 금지)

> 한 줄 제품 경계: 이 시스템은 **___이 아니다** — ___ 운영 도구다. (근거: README/docs 링크)

- **역할 겸직 금지**: 신청자≠승인자 · 작성자≠피평가자 · 결제자≠수취자 · 입력자≠검수자. (구체: `___`)
- **경제 무결성**: 환불 ≤ 수금 · 결제 멱등(중복 webhook 무해) · 가격은 서버 권위(클라이언트 미신뢰). (구체: `___`)
- **게이밍 방지**: 다중계정 혜택 리셋 금지 · self-count 금지 · 무료체험 재발급 차단. (구체: `___`)
- **시간축 권한**: ban/만료/해지 후 보호 동작 즉시 발효(만료 토큰·구독으로 보호 자원 접근 불가). (구체: `___`)

각 불변식은 **음성 케이스(self/cross/replay/state-change-after)를 적어도 1회** 테스트로 태운다 —
happy-path green은 어뷰징 부재를 증명하지 못한다(과녁 부재, 능력 부재가 아님).
```

## 채움 예시 (아키타입별 — 자기 프로젝트의 구체값으로 대체)

**거래/주문 플랫폼 (자금경로):**
- 경제 무결성: 주문 멱등(중복 주문 ID 인식) · 가격/수량은 서버(거래 엔진) 권위, 프론트 캐시 금지 · 계정/엔티티별 손실·노출 상한 강제.
- 시간축: 상태 전이는 명시적 state machine 매트릭스 경유, 정지/만료 후 주문·실행 발화 금지.

**분석/구독 SaaS:**
- 역할 겸직: 분석 사용자 ≠ (해당 시) 심사·승인 주체 · 단일 '정답' 추천으로 책임을 떠넘기지 않음(범위/분포 제시).
- 경제 무결성: 무료 등급이 유료 엔드포인트를 **서버측에서** 접근 불가(클라이언트 토글 무신뢰) · 구독 혜택 리셋 악용 차단.

**결제/청구 플랫폼:**
- 경제 무결성: 환불 ≤ 수금 · 결제 webhook 재조회 후 status·주문ID·금액 대조 + fingerprint 멱등 · 자동매칭은 유일 참조키/단일 정확일치만.
- 역할/격리: 테넌트 격리(RLS는 보조 안전장치) · 결제자/수취자 분리 · 무료체험 다중계정 게이밍 차단.

**접근권한/리소스 시스템:**
- 시간축: 접근 권한 만료/해지 후 보호 리소스(스트림·녹화·다운로드) 접근 즉시 차단.
- 역할: 운영자/뷰어 권한 분리 · 반출·공유 권한 게이팅.

## Fleet 전파 (한 프로젝트 발견을 형제로 자동 확산)

솔로 개발자·다프로젝트·공유 도메인이라, **한 제품에서 찾은 어뷰징 케이스는 같은 클래스를 공유하는 형제 제품에도 거의 항상 존재**한다(예: 거래 플랫폼에서 찾은 환불 전면불능 → 같은 결제 클래스를 쓰는 다른 구독/청구 제품의 환불 경로도 점검). 새 전파 엔진을 만들지 않고 **이미 있는 goals 원장을 재사용**한다.

**공유 클래스 맵(전파 대상 — 자기 fleet의 프로젝트명으로 실측 갱신):**
- **경제 무결성(환불≤수금·멱등·서버권위 가격)**: 결제/자금경로가 있는 모든 제품(거래·주문 플랫폼 · 구독 SaaS · 결제/청구 플랫폼 · 모빌리티/현장결제 등).
- **게이밍(다중계정·무료체험 리셋·self-count)**: 구독형 제품 전반(SaaS · 결제/청구 플랫폼 · 구독형 헬스/피트니스 등).
- **역할 겸직(결제자≠수취자·심사주체)**: 결제/청구 플랫폼 · 분석/구독 SaaS.
- **시간축 권한(만료/해지 후 차단)**: 접근권한/리소스 시스템 · 구독형 SaaS · 민감정보(헬스/PII)를 다루는 제품.

**전파 규율(codebase-audit '어뷰징·무결성' 렌즈가 confirmed 어뷰징 finding을 낼 때):**
1. 그 finding의 클래스를 위 맵에서 찾아 **형제 프로젝트 목록**을 얻는다(자기 fleet 기준으로 구체화).
2. 각 형제의 `.ksi` 원장에 **같은 음성 케이스를 proposed goal로 register**한다(있으면):
   `ksi-goals.py --dir <형제> register --id <FLEET-...> --title "<원 프로젝트>에서 발견한 <클래스> 케이스 — 여기도 점검" --criteria "self/cross/replay/state-change-after 중 해당 음성테스트 통과"`
3. 형제에 원장이 없으면 그 프로젝트 감사 시 이 클래스를 우선 렌즈로 표시(전파는 원장이 있을 때만 자동, 없으면 다음 감사의 조준점).
4. 원본 finding의 verify(reviewer)를 통과한 것만 전파(환각을 형제로 퍼뜨리지 않는다 — 값싼 워커 불신).

이게 fleet 레버다: 한 번의 발견이 N개 형제의 원장에 음성테스트 goal로 박혀, 다음 `/goals run`이 자율로 소진한다(발견→전파→자율수정이 한 substrate에서).
